# 烬土前线 · 联合作战

基于 React、Vite 和 Canvas 的浏览器回合制战棋。全屏六角格沙盘承载战斗，悬浮面板展示任务、战报和当前选中单位；支持二十七个关卡、六类战车、四套编队和三档难度，适配桌面与手机。

## 本地运行

需要 Node.js 20.19+ 或 22.12+，统一使用 npm 管理依赖。

```sh
npm ci
npm run dev
```

打开 <http://127.0.0.1:5173>，选择关卡、难度和编队后部署。

## 操作与规则

| 操作 | 方法 |
| --- | --- |
| 选择单位 | 点击我方车辆；点击可见敌军可查看情报，也会尝试用已选单位开火 |
| 移动 | 点击蓝色可达区域 |
| 维修 | 选择工程车，切换维修模式，再点击相邻受损友军 |
| 平移地图 | 鼠标拖动、手机单指滑动，或触控板双指滑动 |
| 旋转沙盘 | 右键或 Shift + 拖动，手机双指旋转，或「沙盘视角」内旋转按钮 |
| 调整俯视角 | 右键或 Shift + 上下拖动，或「沙盘视角」内角度滑杆 |
| 缩放地图 | 捏合、Ctrl + 滚轮，或加减按钮；普通鼠标的行滚轮也可缩放 |
| 恢复视角 | 点击「沙盘视角」内复位按钮 |
| 撤回操作 | 点击「撤回」，最多保留最近 50 步 |
| 退出关卡 | 点击左上角设置中的「退出关卡」；当前页面会话中可继续战斗 |

每个地格有六个相邻方向。移动使用移动点预算：平地和道路每格 1 点，泥地与浅水每格 2 点；蓝色可达范围按地形总成本计算，车辆会选择更省移动点的路线。深水、山地和树林不可通行。射程、视野和维修按六角格距离计算；山林遮挡穿过或擦过其边缘的视线与直射火力，炮兵可越岭射击，但仍需要共享视野，射程数值本身不变。

每辆车每回合可移动一次、开火一次，顺序不限。工程车可以用开火机会维修友军。**所有存活车辆移动后会自动结束回合**，请在最后一次移动前完成需要的开火或维修；途中发现新的敌军仍会继续驶向指定位置，并保留本回合以便安排火力、其他车辆掩护或撤回。若敌军实际占住路径，则停在其前一格。

我方共享视野，迷雾中的敌人无法被选中或攻击。山林同时遮挡视线和直射火力，敌军可能藏在山背或林后；火炮与火箭炮可越障射击，但有最小射程，并需要友军侦察到目标。道路和桥梁正常通行，浅水可以慢速涉渡，深水必须找桥；山林不可通行。相邻山地使用共享山脊连接成山体，树林使用连续树冠，路径仍按地格判定。

十张原有肃清关卡已改为穿越任务：断脊山隘9车保5、长风峡谷7车保4、双桥河湾9车保6、林海走廊6车保4、环湖交锋8车保5、铁壁峡口9车保6、苇河渡口7车保4、松岭猎场6车保3、雾林岔路6车保4、环礁堤道7车保5。各关保留不同的部署方向，初始沙盘使用无远近缩放的正交桌边视角，按场景从下往上或从左往右推进，编组取所选阵型的前6至9辆。指定数量车辆同时抵达金色撤离区即胜利，存活数量不足要求即失败。

穿越关卡的敌军按沿途三处警戒区分布；哨兵实际看见我方或受到攻击后，只唤醒所在小队。部署预览不显示伏兵位置，避免提前泄露遭遇点。保留五张肃清关卡，以及夺点、工程车护送、坚守等任务。三个战史改编关卡仍以各自目标为准，地图与兵种并非史实复原。

新增五个原创剧情关卡，可在「穿越与护送」分类中选择。静默穿越、渡河脱险、最后车队要求至少 3 辆存活友军同时抵达金色撤离区；存活车辆不足 3 辆即失败。工兵接应、峡谷生命线要求工程车抵达指定地点，工程车被击毁即失败；目标车以金色边框标记，任务栏显示其编号与生命值。这五关均无需歼灭全部敌军，沿途哨兵在友军进入其视野或受到攻击后开始行动。编组按侦察、装甲掩护、工程保障与炮兵支援的分工设计，数值仍使用游戏设定。

新增「地形与守备」四关：泥沼救援提供泥地近路与干燥绕路；浅滩争渡包含可涉渡浅滩和不可通行的深水河槽；独桥封锁要求夺取唯一桥梁两侧桥头；机场防卫要求保护六格跑道区五个完整敌方回合，敌军进入任一保护格立即失败，歼灭敌军可提前获胜。机场具有跑道、停机坪、机库及静态飞机摆件，摆件不参战；不要求车辆持续站在跑道上。泥地表现积水与车辙，浅河表现河床、渡石和涟漪，深水使用独立水色与岸线。

机场防卫 `/battle/airfield-defense` 首次部署时展示可收起的三步守备引导。左侧面板始终显示真实守备轮次、计数条件与仅限当前视野的敌情；金色连续轮廓标出六格保护区，可点击「定位」居中查看。右侧提供本车剩余行动、兵种建议和快捷选车，定位不会移动车辆或消耗行动。守备只在一个完整敌方回合结束后增加；提前全歼会保留实际轮次，不会补成 5/5。跑道被突破和守军全灭分别说明失败原因；撤回恢复战局，重新部署重开引导。

沙盘采用明快的玩具模型风格：浅木托盘、草地、圆润林冠与蓝色河流；六类车辆分别突出轮式座舱、低炮塔、重装甲、长炮、方箱发射架和工程吊臂，使用青蓝奶油色与珊瑚红区分阵营。

车辆移动包含转向、车体起伏和履带扬尘，迷雾独立绘制。地形缓存和按帧合并的视角更新减少重复绘制；系统的「减少动态效果」设置可减弱动画。

操作结果会以短暂提示显示，包含移动、命中、维修、无效指令、任务推进和撤回；最后一辆车移动前会提示剩余开火／维修机会。战场音效覆盖选择、履带推进、开火、命中、击毁、维修、回合交接及胜负，与移动和命中动画配合。声音在首次交互后启用，左上角可静音，设置内可调音量，浏览器会记住设置；快捷键 `M` 切换音效、`Esc` 打开设置。设置和作战指南打开期间暂停敌方行动。

战斗结束后弹出结算窗口，展示回合数、存活车辆和歼敌数，提供「重新部署」和「退出游戏」（返回主菜单），也可撤回最后一步；胜利后可直接前往下一关，沿用难度并使用新关卡推荐编组。战区地图按难度显示通关标记和最佳回合数，记录保存在当前浏览器。

## 页面与部署

战场地址为 `/battle/关卡标识?difficulty=难度&formation=编队`，可直接打开或分享。返回选择页会暂停当前战局；**刷新页面会按地址参数重新开局**，不会保存位置、血量和回合。通关记录与声音设置会保留，但不包含战斗存档。浏览器禁用本地存储或音频时仍可正常游玩。项目不依赖后端，暂未提供战局持久化存档。

```sh
npm run build    # 输出 dist/
npm run preview  # 在 http://127.0.0.1:4173 预览构建
```

将 `dist/` 部署到站点根路径，并配置 SPA 回退：访问 `/battle/*` 时返回 `index.html`，以支持刷新和直接进入关卡。

## 验证

```sh
npm test                         # 游戏规则、状态与渲染计算
npx playwright install chromium # 首次运行浏览器测试前安装
npm run test:e2e                  # 浏览器交互和响应式布局
```

浏览器测试默认使用 Playwright 的 Chromium，并自动启动或复用本地开发服务。需要使用本机 Chrome 时，运行 `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`。

## 代码结构

```text
src/
  App.jsx          页面路由与战局入口
  components/      关卡选择、战场、单位面板和指南
  hooks/           游戏生命周期、战场绘制与输入交互
  game/            车辆、编队、关卡、战斗规则与状态更新
  rendering/       投影、拾取、地形缓存、车辆、迷雾与战斗特效
  styles.css       基础界面与关卡选择页样式
  styles/battle.css  战场 HUD 与响应式布局
tests/             Node 测试及 browser/ 下的 Playwright 测试
```

新增关卡从 `src/game/scenarios.js` 入手，车辆属性见 `src/game/catalog.js`；规则与状态分别集中在 `engine.js` 和 `reducer.js`。显示数据由战局状态派生，调整数值时以这些定义为准。

首页 `/` 为全屏主菜单，点击“开始游戏”进入 `/operations` 关卡页，关卡以据点分布在战区地图上，点击据点直接部署；可在旁侧统一选择难度与编组。新增赤沙回廊（机动迂回）、石湾三桥（分路渡河）、锯齿防线（越岭炮击）、雾林岔路（林间侦察）、环礁堤道（绕湖推进）和断层要塞（多层防线突破）。
